# SKILL: Weekly Content Operating System

## СВОЯ by КОУЧ — Операційна система тижневого контенту

---

## ГОЛОВНА МЕТА

Не просто створювати контент.

Створювати стабільний цикл:

```text
Cloudinary / Local Upload / Future Zoom
↓
Transcript
↓
Weekly Analysis
↓
Content OS
↓
Social Proof
↓
Sales Assistant
↓
AI Mentor
```

### Канонічний принцип

- Аудіо не є джерелом інтелекту.
- Транскрипт є джерелом інтелекту.
- Один транскрипт генерується один раз і використовується всюди.
- Будь-який повторний контент-план повинен читати готові транскрипти, а не запитувати те саме знову.

---

## ЯК ВЕСТИ КОУЧА — ЗАГАЛЬНИЙ ПРИНЦИП

На початку кожної сесії планування показати прогрес-бар кроків:

```text
📍 Зараз: Аналіз тижня
⬜ Далі: Бізнес-сигнали → Інсайти → Тема → Контент-план
```

- Після кожного блоку показувати, що зібрано.
- Питати підтвердження перед переходом далі, якщо є неоднозначність.
- Не задавати більше 2 питань одночасно.
- Якщо вже є transcript, не питати повторно те, що вже в ньому міститься.

### Головне правило контент-логіки

- Спочатку збираємо сигнали.
- Потім формуємо інсайти.
- Потім обираємо тему.
- Лише після цього будуємо план.
- Якщо чогось не вистачає, позначаємо `MISSING SOURCES`, а не вигадуємо.

Або одразу плануємо — і ти розкажеш що було по ходу?

Якщо КОУЧ хоче одразу план — пояснити коротко:

```text

щоб контент відображав реальне, а не вигадане.

```

Якщо transcript уже існує:

- одразу читати transcript
- не просити тему Zoom повторно
- не питати “що було по ходу”, якщо це вже є в транскрипті

## КРОК 1 — ДЖЕРЕЛА ІНТЕЛЕКТУ

**Показати КОУЧУ:**

```text
📍 Крок 1 з 6 — Джерела інтелекту
```

### Джерела, з яких будується контент

| Джерело          | Що дає                                   | Як використовується         |
| ---------------- | ---------------------------------------- | --------------------------- |
| Transcript       | Тема, цитати, болі, прориви, заперечення | Базове джерело для всього   |
| Focus Results    | Результати, зміни, соціальний доказ      | Для продажів і прогріву     |
| Sales            | Оплати, кліки, заперечення               | Для теми, CTA і дожиму      |
| Direct           | Питання, болі, фрази аудиторії           | Для заголовків, сторіс, CTA |
| Stories Feedback | Реакції, відповіді, сенс, збереження     | Для корекції подачі         |

### Канонічний порядок читання

1. Transcript
2. Focus Results
3. Sales
4. Direct
5. Stories Feedback

### Статус готовності

- `READY` — всі потрібні джерела є
- `MISSING SOURCES` — частини даних не вистачає

Якщо transcript уже є:

- використовувати його як основний інпут
- не просити людину заново описувати Zoom
- не будувати план на здогадках

### Типи Zoom і система іменування

| Тип                    | Назва файлу                   | Кількість за тиждень | Аналізується як           |
| ---------------------- | ----------------------------- | -------------------- | ------------------------- |
| Групова практика ФОКУС | `FOCUS_ZOOM_дд.мм.рррр_01`    | 1–2                  | Контент + бізнес-сигнали  |
| Індивідуальна сесія    | `IND_ім'я_дд.мм.рррр_КОУЧИНГ` | 1–5+                 | Патерни болю, НЕ публічно |
| Майстермайнд           | `MASTERMIND_дд.мм.рррр`       | рідко                | Контент + цитати          |

| Воркшоп                | `WORKSHOP_тема_дд.мм.рррр`    | разово               | Окремий контент-пакет     |
| Кейс                   | `KEYS_тема_дд.мм.рррр`        | разово               | Окремий контент-пакет     |

### Правила по типах

- **Групова практика ФОКУС** — головне джерело для контент-плану
- **Індивідуальна сесія** — патерни болю, не публічно
- **Майстермайнд** — цитати і теми для продажу ФОКУС
- **Інтенсив / Воркшоп / Кейс** — окремий контент-пакет

### Якщо один Zoom або один transcript

Питання по 2:

```text
1. Яка була тема Zoom цього тижня?
2. Який момент викликав найбільшу реакцію групи?
```

Після відповіді:

```text
3. Яке питання люди повторювали найчастіше?
4. Що тебе особисто найбільше зачепило?
5. Яку тему хочеться продовжити наступного тижня?
```

Після відповіді завжди витягти:

- тему
- ключовий момент
- домінуючий біль
- найсильнішу цитату
- що резонувало найбільше

### Якщо transcript уже має ці відповіді

- не перепитувати
- брати готові формулювання з transcript
- уточнювати лише якщо дані суперечливі або уривчасті

### Якщо два і більше Zoom за тиждень

Аналізувати окремо, потім зведено.

Формат виводу:

```text
━━━ ZOOM 1 — [тип] [дата] ━━━
Тема: [...]

Домінуючий біль: [...]
Найсильніша цитата: [...]
Що резонувало найбільше: [...]

━━━ ZOOM 2 — [тип] [дата] ━━━
Тема: [...]
Ключовий момент: [...]
Домінуючий біль: [...]
Найсильніша цитата: [...]
Що резонувало найбільше: [...]

━━━ ЗВЕДЕНИЙ ІНСАЙТ ━━━
Спільний біль обох Zoom: [...]
Де теми перетинаються: [...]
Найсильніша думка тижня: [одна фраза]
Найкраща цитата для Reel: [...]
Найкраща цитата для Stories: [...]

```

### Правила аналізу по типах

**Групова практика ФОКУС** → основне джерело для контент-плану:

- Що говорила група → теми для Reel і одна думка
- Цитати учасників → Stories і охоплення
- Питання, що повторювались → тема наступного тижня

**Індивідуальні сесії** → патерни болю, НЕ публічний контент:

- Не використовувати конкретні деталі особистих сесій
- Використовувати тільки загальні патерни: “багато людей зупиняє X”
- Ніяких імен, ніяких деталей ситуацій

**Майстермайнд** → цитати і теми для продажу ФОКУС:

- Що учасники говорили про результати → соціальний доказ
- Прориви → Stories після Zoom

**Інтенсив / Воркшоп / Кейс** → окремий контент-пакет (Zoom Calendar Mode)

### Якщо Zoom не було

```text
Zoom цього тижня не було — окей.
Розкажи: що ти сама проживала цього тижня?
Яка думка або ситуація зупиняла?
```

Альтернативні джерела:

- Особистий стан КОУЧУ
- Аналітика SaaS: тип результатів тесту, кліки на ФОКУС, оплати

## КРОК 2.5 — РЕЗУЛЬТАТИ УЧАСНИЦЬ І СОЦІАЛЬНИЙ ДОКАЗ

Після відповіді:

```text

4. Що змінилося після Zoom або практики?
5. Хто прийшов у ФОКУС із сумнівами але зараз радий що залишився?
```

**Джерела кейсів:**

- Голосові повідомлення в каналі `https://t.me/+wCcab6F5-uU1OTdi`
- Аудіо Zoom-записи з каналу «Аудіо ЗУМИ ФОКУС»
- Скріншоти переписки з дозволу учасниці
- Усний ввід від КОУЧУ

### Що витягти після відповідей:

**Цитата довіри** — що людина сказала своїми словами до або на початку ФОКУС

**Цитата трансформації** — що змінилось після роботи у ФОКУС

**Соціальний доказ** — формат:

```text
“Ще [минулого тижня / місяць тому / на початку]...
Сьогодні...”
```

**FOMO-сигнал** — що зараз відбувається всередині ФОКУС але не бачать люди зовні?

**Цитата для Reel** — одна сильна думка, без пояснень

**Цитата для Stories** — коротко, емоційно, живо

### Контент-пакет для підписників тесту (10х конверсія)

На основі результату учасниці сформувати:

| Формат            | Тема                                | CTA                             |
| ----------------- | ----------------------------------- | ------------------------------- |
| Stories (3 кадри) | “Що зараз відбувається у ФОКУС”     | “Хочеш так само — напиши ФОКУС” |
| Reel              | “Результат учасниці” — її словами   | “Напиши ФОКУС в директ”         |
| Пост / одна думка | “Що змінилось після рішення прийти” | питання до аудиторії            |
| Дожим (бот)       | Цитата учасниці як соціальний доказ | кнопка “Оплатити ФОКУС”         |

> Цей контент показується підписникам які пройшли тест але ще не купили.
> Мета: зняти сумніви через живий результат людини схожої на них.

### Правила роботи з кейсами

```text
✅ Використовувати тільки реальні зміни і реальні формулювання
✅ Перефразовувати якщо є ризик впізнавання без дозволу
✅ Ім'я — тільки з явного дозволу учасниці
✅ Деталі особистих ситуацій — не публічно, тільки загальний патерн

❌ Вигадувати результати
❌ Перебільшувати
❌ Використовувати особисті дані без дозволу
❌ Розкривати деталі індивідуальних сесій
```

### Мінімум для кожного тижня

Кожен тижневий план має містити мінімум:

```text

□ 1 цитата учасниці її словами
□ 1 результат після Zoom або практики
□ 1 FOMO-сигнал (що відбувається всередині ФОКУС)
```

Якщо жодного з цього немає — повернутись до КОУЧУ і запитати.

## CONTENT GENERATION LOGIC

### Канонічний алгоритм

1. Отримати джерела.
2. Перевірити, чи є transcript.
3. Якщо transcript є — використати його як базу.
4. Якщо transcript відсутній — зупинитись і позначити `MISSING SOURCES`.
5. Зібрати інсайти з:
   - transcript
   - sales
   - direct
   - stories feedback
   - focus results
6. Виділити:
   - біль
   - прорив
   - заперечення
   - цитати
   - FOMO
   - тригери покупки
7. Обрати тему тижня.
8. Згенерувати контент-план.
9. Перевірити бізнес-ціль кожного поста.
10. Якщо хоча б один пост не веде до довіри / директу / тесту / ФОКУСу — виправити.

### Що НЕ робити

- не генерувати план без аналізу
- не просити повторно те, що вже є в transcript
- не використовувати raw audio як джерело мислення
- не будувати контент лише на “красивій темі”
- не підміняти реальні сигнали вигадкою

## ZOOM CALENDAR MODE

Якщо КОУЧ планує наступний Zoom — окремий режим:

Запитати:

```text
1. Яка тема наступного Zoom?
2. Який головний біль групи хочеш розібрати?
3. Який результат хочеш що люди отримали після?
```

Після відповіді сформувати:

```text
📅 ZOOM CALENDAR PACK

1. Анонс Zoom (пост або Stories за 3 дні)
2. Контент до Zoom — підігрів теми
3. Stories до Zoom — “готуєшся?”
4. Контент після Zoom — розкрити один інсайт
5. Stories після Zoom — реакції, цитати
6. Цитати для продажу ФОКУС із цієї теми
7. Теми наступного тижня що виросли з Zoom
```

### Правило календаря

- календар будується лише після transcript/аналізу
- якщо тема вже є у transcript, не питати її повторно
- якщо є кілька Zoom, зводити їх окремо і потім у спільний інсайт

## TRANSCRIPT SELECTOR RULES

### Для web-платформи

- показувати тільки transcripts
- default: `Select Existing Transcript`
- не показувати raw audio files
- не показувати video files
- фільтр: поточний тиждень + 4 попередні тижні
- базуватися на Monday boundaries

Приклад:

```text
☑ ФОКУС 02.06.2026
☑ ФОКУС 26.05.2026
☑ ФОКУС 19.05.2026
☑ KEYS 28.05.2026
```

### Для Telegram Bot UI

- використовувати multi-select checkboxes
- можна вибирати кілька transcript одночасно
- Content OS аналізує лише обрані transcripts

Приклад:

```text
☑ ФОКУС 02.06.2026
☑ ФОКУС 26.05.2026
☑ ФОКУС 19.05.2026
☐ KEYS 28.05.2026
```

### Принцип вибору

- transcript exists → reuse
- transcript not found → generate once
- raw audio never becomes direct input for content planning

## БІЗНЕС-ПЕРЕВІРКА КОНТЕНТУ

Кожен пост, сторіс або reel має відповідати хоча б одній меті:

| Ціль   | Що має відбутися                     |
| ------ | ------------------------------------ |
| Довіра | Людина відчула: “це про мене”        |
| Директ | Людина написала в приват             |
| Тест   | Людина заповнила тест / квіз / форму |
| ФОКУС  | Людина купила / подала заявку        |

Якщо контент не веде ні до однієї з цих цілей:

- позначити `⚠️ CONTENT WITHOUT BUSINESS PURPOSE`
- не включати в план

## ГНУЧКІСТЬ ПО СИТУАЦІЯХ

| Ситуація                | Дія                                                    |
| ----------------------- | ------------------------------------------------------ |
| Zoom не було            | Особистий стан КОУЧУ + SaaS аналітика                  |
| Є transcript            | Використати transcript як базу                         |
| Немає transcript        | Повернути `MISSING SOURCES`                            |
| КОУЧ хоче одразу план   | Збирати дані паралельно — 1-2 питання між блоками      |
| Контент без чіткої цілі | Уточнити мету, запропонувати варіант з ціллю           |
| Відступ від архетипу    | Нагадати, запропонувати альтернативу, але не блокувати |

## КОРОТКА ПАМ'ЯТКА

1. Transcript — source of truth.
2. Audio is only intake.
3. One transcript is generated once.
4. All downstream systems read transcript, not raw audio.
5. Weekly Content OS starts with sources, not ideas.
6. If source data is missing, say `MISSING SOURCES`.
7. No repeated questions if transcript already has the answer.
8. Every content piece must serve trust, direct, test, or Focus.
