# SKILL: Product Specification Auditor

Version: 2.0
Priority: Critical
Scope: All PRDs, TЗ, Product Specs, User Flows, Telegram Bots, SaaS Platforms, AI Systems

## CORE RESPONSIBILITY

Перед виконанням будь-якого ТЗ виконати повний аудит документа.

Завдання скіла:

1. Знайти відсутні блоки.
2. Знайти зайві блоки.
3. Знайти дублікати.
4. Знайти суперечності.
5. Знайти розірвані сценарії.
6. Знайти відсутні повідомлення.
7. Знайти відсутні меню.
8. Знайти відсутні статуси.
9. Знайти відсутні lifecycle transitions.
10. Знайти блоки які більше не потрібні.

---

## MANDATORY REVIEW

Для кожного нового ТЗ виконати:

### ADD AUDIT

Що потрібно додати?

Шукати:

* відсутні стани
* відсутні меню
* відсутні повідомлення
* відсутні кнопки
* відсутні сторінки
* відсутні recovery сценарії
* відсутні edge cases
* відсутні permission checks
* відсутні subscription states
* відсутні onboarding states

---

### REMOVE AUDIT

Що потрібно прибрати?

Шукати:

* мертві сценарії
* дублікати функцій
* дублікати меню
* дублікати кнопок
* дублікати повідомлень
* застарілі екрани
* legacy flows
* непотрібні переходи
* функціонал який не використовується

---

### SIMPLIFICATION AUDIT

Шукати:

* два блоки які можна об'єднати
* три повідомлення які можна зробити одним
* дублювання логіки
* дублювання станів
* дублювання API

---

### CONSISTENCY AUDIT

Перевіряти відповідність:

UI

Telegram

Backend

Database

Lifecycle

Permissions

Navigation

Якщо логіка різна:

⚠️ INCONSISTENT SPECIFICATION

---

## FLOW COMPLETENESS AUDIT

Для кожного етапу перевіряти:

Як користувач потрапляє сюди?

Що бачить?

Що може зробити?

Що буде далі?

Що буде після reload?

Що буде після повторного входу?

Що буде після повернення через день?

Що буде після повернення через місяць?

---

## STATE MACHINE AUDIT

Для кожної сутності перевіряти повний lifecycle.

Приклад:

NEW_USER

TEST_STARTED

TEST_COMPLETED

LEAD

PAYMENT_PENDING

SUBSCRIBER

EXPIRING

EXPIRED

RENEWED

CANCELLED

Якщо переходу немає:

⚠️ STATE GAP DETECTED

---

## USER AWARENESS AUDIT

Користувач повинен завжди знати:

Де він?

Що вже відкрито?

Що закрито?

Що буде далі?

Скільки часу залишилось?

Як продовжити?

Як відновити доступ?

Якщо ні:

⚠️ USER AWARENESS GAP

---

## CHANGE IMPACT AUDIT

При кожній зміні ТЗ перевіряти:

Що ця зміна ламає?

Які екрани зачіпає?

Які API зачіпає?

Які ролі зачіпає?

Які меню зачіпає?

Які повідомлення зачіпає?

Які автоматизації зачіпає?

Якщо вплив не описаний:

⚠️ CHANGE IMPACT NOT ANALYZED

---

## OUTPUT FORMAT

Перед реалізацією завжди формувати:

### Missing

Список того що треба додати.

### Remove

Список того що треба прибрати.

### Simplify

Список того що можна спростити.

### Risks

Список ризиків.

### Recommended Changes

Конкретні блоки для оновлення ТЗ.

---

## FINAL RULE

Не вважай ТЗ завершеним.

Вважай його чернеткою.

Завжди шукай:

Що додати?

Що прибрати?

Що об'єднати?

Що спростити?

Що стане проблемою через 3 місяці?

Що стане проблемою при 1000 користувачах?

Що стане проблемою після наступної зміни продукту?

Поки на всі питання немає відповіді — ТЗ вважається неповним.
